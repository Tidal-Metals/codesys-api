1. Generate a working native device

A working result needs four pieces: the Ethernet/client/server device tree, configured Modbus channels, typed ST storage, and I/O mappings linking those channels to that storage. Generating ST alone does not create native Modbus communication.

CODESYS calls the PLC-side parent a Modbus TCP Client and each remote-device child a Modbus TCP Server. Each native server child establishes an outbound TCP connection. Multiple channels under that child share its unit ID; separate unit IDs use separate children and connections in this tested configuration.

Start from the approved controller base. Preserve NetConfig and unrelated modules. Bind the Ethernet node to the intended physical port; the tested native tree uses ETH2. Adding an Ethernet tree node does not itself configure the physical port address.
Create or reuse Ethernet → TCP Client → remote server. Prefer the bundled GatewayUnit1_20260924.export as the known-good channel template. The larger ETH2NativeBench_20260924.export contains the parent tree, ten gateway nodes and one PC node. Import into a disposable project first, preserve unique names/identities and rebind every mapping.
Set endpoint and channel. For unit 1: gateway 192.168.50.151:502, response timeout 2000 ms; FC03, zero-based register offset 0, count 2, cyclic interval 1000 ms. A gateway endpoint and a logical unit are different concepts. Register documentation using 40001 notation must be translated to protocol offsets explicitly.
Declare and map raw storage. Map the complete two-word input channel to Application.PLC_PRG.GatewayRegisters. Generate decoding/scaling separately and preserve signedness, byte/word order and quality. Keep the owning POU in an active task; the native bench uses a 50 ms task.
Rebuild and inspect the result. Assert zero compiler errors, read back parameters and mappings, then save. Download/start only the authorized bench application. Verify the online application matches the project; save a boot application when the tested result should survive power loss.

The existing channel/native-export helpers in codesys-api are useful references, but parts assume serial Modbus. In particular, generic device creation defaults to a serial device, not type 89, and generic updates do not provide a complete typed TCP endpoint contract.

# Verified mapping adapter for the installed device description.
import clr
clr.AddReference('DeviceObject')
parent = node.connectors[0].host_parameters.parent
iface = [i for i in parent.GetType().GetInterfaces()
         if 'IParameterSetContainer' in i.Name][0]
ps = iface.GetProperty('ParameterSet').GetValue(parent, None)
matches = [q for q in ps if q.VisibleName == 'GateRead'
           and str(q.ChannelType) == 'Input']
assert len(matches) == 1
channel = matches[0]
assert channel.SubElements.Count == 2
stack = [channel]
while stack:
    sub = stack.pop()
    maps = sub.IoMapping.VariableMappings
    while maps.Count:
        maps.RemoveAt(0)
    if sub.HasSubElements:
        stack.extend(list(sub.SubElements))
channel.IoMapping.VariableMappings.AddMapping(
    'Application.PLC_PRG.GatewayRegisters', False)

# Native export of an existing configured node:
project.export_native([node], fresh_output_path, True, False, None, None)

Isolate this version-specific adapter. Direct mapping changes have previously failed to invalidate compiled output; a full rebuild and live mapping verification are required. The repair script also toggled a normal response-timeout parameter 2000 → 2001 → 2000 to invalidate configuration. Do not rely on “saved successfully” as proof of updated runtime I/O.

Information the generator must represent

Keep physical Ethernet binding, endpoint IP/port, unit ID, channel function, zero-based offset, quantity, cyclic period, response timeout, access policy, variable mapping and data decoding explicit. Define device quality/error handling independently from value storage. Validate register widths, unique generated names and gateway connection capacity. A repeat generation should update owned objects without duplicating them or modifying unrelated modules. This is a checklist, not a prescribed schema.

Local simulator and direct-read commands

Run on the bench PC from codesys-api, after checking existing owners. These commands are reference launch commands, not an instruction to start duplicates. Installed versions: Python 3.13, pymodbus 3.15.0, pyserial 3.5. The TCP simulator imports support code from the bundled RTU simulator, so keep them together.

python modbus_rtu_slave_sim.py --port COM18 --baudrate 38400 --bytesize 8 --parity N --stopbits 1 --multidrop --manifest examples/modbusfb_single_connection/rtu_devices.json

Supply all ten fixtures when replacing the ten-device simulator. The API default baud is 9600, so always specify 38400 for the current two-adapter bench. The current manager tracks its own PID records, stops those recorded processes and starts replacements. It does not reliably prove device ownership, traffic health or successful termination; improve these checks before using it as an unattended bench controller.

Recommended extension, not implemented: extend the authenticated bench service with resource inventory, exclusive test ownership, safe start/stop/reconfigure for RTU and TCP simulators, register-value and silent-unit controls, source-bound TCP probes, and traffic counters with last RX/TX timestamps. Identify the FTDI adapter by serial number and the ASIX by MAC, then resolve current COM/IP assignments. Verify command/device identity before stopping a recorded PID. No raw serial-over-TCP tunnel is needed for the primary test: the service runs the RTU simulator beside COM18 and exposes configuration/results over HTTP.

Keep IDE mutations serialized. A persistent-session script should use one shared execution namespace when defining helpers, for example scope = dict(globals()); exec(code, scope, scope). A timed-out HTTP call may still execute later; inspect the project before retrying a non-idempotent operation.

4. Verification sequence
Inventory and isolate. Check API attachment, active project and PLC identity; resolve DHCP addresses and serial ownership. Back up the project. Use a separate generated bench project or clearly owned test subtree; do not edit unrelated modules.
Prove TCP and native mapping first. Generate one child targeting PC .155:502, unit 1, FC03/0/2. Rebuild/download/run. Require values 1234/5678, no server xError, and repeated requests visible at the PC. This bypasses gateway and RS485.
Prove gateway forwarding. Once COM18 traffic is healthy, test one unit through .151:502, then all ten with five children on each socket. Match every unit's distinct data and record actual request/reply counts.
Measure a steady interval. After startup/recovery settles, sample at least 60 seconds: correct values, stable connection tuples, advancing per-unit traffic, no new error/bad-value counter increments. Compare counter deltas, not historical totals. For the restored project, use ValuesMatch, AllTenRTUValuesMatch, AllTenRTUHealthy and per-unit TenErrorCycles/TenBadValueCycles.
Fault and recover deliberately. Silence one simulated unit while leaving the other nine responding. Require that unit to become invalid/error, continued good data from the others, and recovery when restored. Separately test TCP peer loss and recovery. Report any reconnects, including native-driver behavior, rather than assuming a serial timeout must preserve TCP.
Persist the verified result. Save generated artifacts, compiler result, actual parameters/mappings, traffic evidence and quality behavior. Save/download the intended boot application and release simulator/test ownership.
5. Common footguns
Connection limits: this firmware was tested with five connections on A and five on B. A sixth on one socket can connect at the TCP layer but receive ASCII “Sorry,Limited number of connections” instead of Modbus. Ten PLC children occupy every tested slot; release the relevant PLC connections before a PC probe. The master’s xStop can pause polling while healthy sockets remain open; verify an actual free slot. For this test, pausing the PLC and restarting only the bench gateway released them. Do not assume xStop alone disconnects. B adds TCP slots, not another RS485 bus.
Gateway mode: Multi Host is required for the tested multiple-client arrangement. Simple mode caused field trouble when separate native children opened multiple connections. Do not silently replace it with configurable/cached polling mode; cached success can hide a missing RTU device.
Two physical responders: separate unit IDs alone are insufficient with this simulator. Use --multidrop (API multidrop: true) on both ports, at 38400 baud or lower. Without it, the second simulator can emit exceptions for the other device’s requests or replies. A regression test now exercises the actual framer against captured foreign traffic.
USB reconnection: an unplug/reseat invalidated COM18’s handle and produced ClearCommError: Access is denied. PyModbus’s background reader stopped while its process remained alive. Reopen/restart the port owner after a USB reconnect; a live PID is not sufficient proof of health.
Physical and process health: previous loose RS485 wiring and the recent stuck COM18 process both broke tests. TX LEDs, a live PID or a successful TCP connection are insufficient; require valid serial replies and expected PLC data. Do not assign every TCP_COMMUNICATION_ERROR to the IP network.
Mappings: CSV import can leave an unmapped or wrongly mapped channel. Map the complete input array once; clear competing root/leaf mappings. Correct channel structure, declared variable type, task execution and I/O update behavior all matter.
IDE dialogs and stale builds: file-in-use, overwrite and update dialogs block the persistent script. Close all export/CSV handles; use fresh filenames. Inspect native mappings after import and rebuild before download. GUI warning icons may lag actual runtime status.
Addresses and routes: .151 is the bench gateway, .155 the USB Ethernet lease; .123 is not the gateway. Both PLC Ethernet ports are on the same subnet in this bench, so record which interface actually carries traffic. Do not generalize this topology into an unverified deployment default.
Timing and representation: distinguish task period, channel cycle, response timeout, gateway RTU timeout and data age. The ModbusFB timeout inputs in the included example use microseconds; native response/channel parameters here use milliseconds. Verify zero-based offsets, signed values, register widths and word order.
6. Alternative: ten unit IDs over one connection

The included FB_ModbusTenUnits.st owns one ModbusFB.ClientTCP and reuses ClientRequestReadHoldingRegisters sequentially with a different uiUnitId. Keep the ID and buffer fixed until each request completes, reset xExecute between requests, update per-unit validity, and move on after a timeout. A request error does not automatically require closing the shared TCP connection. This option replaces the ten native server children; it is not the primary generator scope.

Use ModbusFB 4.5.0.0 and Standard, import ModbusTenUnits.export, and call its POU cyclically. The tested fast version uses a 5 ms task, no added request gap, 115200/8N1, gateway A:502. Complete code is in the ZIP.
